## 3. システム構成（ED27）

Webアプリ1つと、教室PCで動く受付アプリ1つで構成する。学生・教員は普段のブラウザからWebアプリを使い、出席申告だけは受付アプリがカードリーダーから学生証を読んでWebアプリのAPIに送る。

受付アプリとブラウザはどちらも同じWebアプリのAPIを呼び、**DB・認証・メールにはWebアプリだけが接続する。**

- 受付アプリを分ける理由: RC-S300 は Windows 上で PC/SC（ICカードリーダーの標準規格）で読める。ブラウザから直接読む WebUSB は Windows ではドライバの差し替えが必要で、学校のPCでは難しい可能性が高いため。
- 判定はサーバ時刻で行う。教室PCの時計がずれていても、出席・遅刻の境目は変わらない。

### 3.1 採用技術（案）

| 区分 | 採用技術（案） | 備考 |
|---|---|---|
| Web画面 | React ＋ TypeScript | PC・スマートフォン両対応の画面 |
| Web API | Node.js ＋ TypeScript | REST API、MVC構成 |
| データベース | MySQL | テンプレートの例に合わせた。PostgreSQL でも可 |
| Webサーバ | Nginx | HTTPS化 |
| 受付アプリ | C#（.NET、WPF） | PC/SC で学生証のIDを取得し、結果を画面と音で表示 |
| 認証 | Microsoft Entra ID（OpenID Connect） | 受付アプリも教員アカウントでサインイン |
| メール（希望） | Microsoft Graph API | 欠課警告メールの送信 |

### 3.2 共通方針

| 項目 | 方針 |
|---|---|
| 文字コード | UTF-8 |
| 対応言語 | 日本語のみ |
| 排他制御 | 楽観的排他制御（更新バージョン列） |
| 認証方式 | Microsoft 365 アカウントのみ。ID・パスワードは本システムで持たない |
| セッション | Webは最終操作から30分で失効。受付アプリは受付中の授業が終わるまで維持 |

## 6. 出欠受付の処理設計（ED02・ED04）

出欠は「授業回」（ある日のある授業1回）ごとに記録し、判定はサーバがかざした時刻で行う。受付アプリは読み取りと表示だけを担当する。

### 6.1 判定ルール

| かざした時刻（サーバ時刻） | 判定 |
|---|---|
| 授業開始時刻まで | 出席 |
| 開始時刻を過ぎ、開始後15分00秒まで | 遅刻 |
| 開始後15分より後 | 欠課 |
| 授業終了まで申告なし | 欠課（締切時に自動で登録） |

欠課時数は授業ごとに次の式で計算する。**公欠は数えない。**

- 欠課時数 ＝ 欠課回数 × 1回あたりの時間数 ＋ 遅刻回数を3で割った商
- 1回あたりの時間数は授業ごとに設定し、初期値は2（90分の授業を2時間と数える想定）
- 上限までの残り ＝ 欠課上限時間（授業ごとに設定、R-02-5）－ 欠課時数

### 6.2 学生証をかざしたときの処理（A_S0001）

1. 受付アプリが PC/SC で学生証のカードIDを読む。読めなければ「もう一度かざしてください」を表示する（`A_S0001_W000001`）。
2. 受付アプリが授業回ID・カードID・受付トークンをAPIに送る。サーバは受付中の授業回か確かめ、締切後なら「受付が終了しています」を返す（`E000003`）。
3. 有効な学生証として登録されていなければ「登録されていない学生証です」を返す（`E000001`）。
4. その授業の受講学生でなければ「この授業の受講学生ではありません」を返す（`E000002`）。
5. すでに申告済みなら「申告済み」を返し、記録は変えない（`I000002`）。
6. 6.1のルールで判定し、出欠テーブルに1件登録する。「授業回×学生」の一意制約で、同時に2回かざしても二重にならない（R-01-3）。
7. 氏名と結果を返し、受付アプリが色と音で表示する。申告人数／受講者数も更新する。

エラーを含むすべてのタッチはタッチログに残し、他人の学生証による申告の調査に使えるようにする。

### 6.3 受付の開始と終了

- 開始: 教員が受付アプリにサインインすると、担当授業のうち今の時刻に合う授業回が自動で選ばれ、「受付開始」の1ボタンで始まる。開始できるのは授業開始の30分前から（設定値）。
- 終了: 教員が「受付終了」を押すか、授業の終了時刻に受付自動締切（A_B0001）が締め切る。締切時、記録のない受講学生を欠課（入力区分＝自動）で登録する。

### 6.4 受付画面の主な項目（A_S0001_SD0001）

| No. | 項目名 | 項目種別 | 表示タイミング | 備考 |
|---|---|---|---|---|
| 1 | 授業名・時限・教室 | ラベル | 受付中 | 自動選択した授業回。変更も可 |
| 2 | 受付開始／終了ボタン | ボタン | 常時 | 教員の操作はこの1ボタンだけ（3.2.4） |
| 3 | 判定結果 | パネル | かざした直後3秒 | 氏名＋結果。出席＝緑、遅刻＝黄、欠課・エラー＝赤、申告済み＝青。成功音とエラー音の2種類 |

### 7.2 ER図（関連の要約）

原本のER図は貼り付けテキストに含まれていない。表から読み取れる関連は次のとおり。

- teacher_mst 1 — N course_mst（担当）
- period_mst 1 — N course_mst（時限）
- course_mst 1 — N enrollment_mst N — 1 student_mst（受講）
- course_mst 1 — N class_session_trn（授業回）
- student_mst 1 — N student_card_mst（学生証）
- **出欠は授業回と学生の両方にぶら下がる:** class_session_trn 1 — N attendance_trn N — 1 student_mst
- attendance_trn 1 — N attendance_history_trn（出欠修正履歴は修正した教員 teacher_id とも関連する）
- class_session_trn 1 — N card_touch_log_trn

## 10. セキュリティと権限（ED24）

ロールは学生と教員の2つだけ。**誰のデータを見せるかは、画面から送られたIDではなく、サーバがサインイン情報から決める。**

### 10.1 ロールと参照可能範囲

| 画面・操作 | 学生（ROLE0001） | 教員（ROLE0002） |
|---|---|---|
| 学生ホーム・授業別出欠記録 | 自分の記録のみ | 不可 |
| 教員ホーム・出欠一覧・欠課時数一覧・書き出し | 不可 | 担当授業のみ |
| 出欠修正 | 不可（R-04-3） | 担当授業のみ |
| 授業・授業回・受講学生登録 | 不可 | 自分の授業のみ |
| 学生・学生証登録 | 不可 | 可 |
| 受付アプリの受付開始・終了 | 不可 | 担当授業のみ |
| 学生証をかざす | 可 | — |

ロールは、サインインしたメールアドレスが student_mst にあれば学生、teacher_mst にあれば教員と判定する。どちらにもなければ `SYSCOMMON_E000101` を表示する。

### 10.2 セキュリティ対策

| 対策 | 方針 |
|---|---|
| 認証 | Microsoft Entra ID でサインイン。未サインインのAPI呼び出しはすべて拒否 |
| 認可 | 学生ID・教員IDはサーバが認証トークンから決め、全APIで担当授業かを確かめる |
| 通信 | HTTPSのみ（受付アプリも含む） |
| 受付APIの保護 | 受付開始時に授業回ごとの受付トークンを発行し、締切で失効させる。受付アプリ以外からは申告できない |
| 代理申告の抑止 | かざしたときに氏名を表示、申告人数／受講者数を表示、全タッチをログに残す（3.2.2） |
| 改ざん防止 | 出欠の更新APIは教員にだけ公開し、修正は理由と変更前後を履歴に保存する |
| XSS | React の自動エスケープを使い、HTMLの直接埋め込みを禁止 |
| SQLインジェクション | プリペアドステートメントのみ使う |
| CSRF | Cookie を SameSite=Lax にし、更新系APIに CSRF トークンを付ける |
| 個人情報 | 学生証のカードIDは画面に出さない。DBは外部から直接接続できない場所に置き、バックアップは暗号化する |
